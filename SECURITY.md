# Security and public data

Keep credentials and identifying data outside Git, including Git history. Use ignored local environment files or a secrets manager. If a credential is accidentally published, revoke or rotate it before removing it from history.

Use synthetic examples in issues, screenshots and demonstrations. Do not post access tokens, identifying recordings, customer records or confidential sponsor material in a public issue.

Report vulnerabilities through GitHub's private vulnerability reporting option if enabled, or contact a maintainer privately through their GitHub profile. This hackathon project has no guaranteed response time.

Camera images, voices and bystanders can identify people. Do not put raw participant recordings, consent forms or device tokens in public Git. Optional recordings need explicit consent, restricted storage and a deletion plan. A camera LED alone does not establish consent for a user study.
